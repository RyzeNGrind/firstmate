  {"sessions":[{"default":true,"name":"default","running":false,...}]}

Reason it is untested here:
  - bin/fm-herdr-lab.sh:79 requires `running == true` on the default session as
    a tripwire before it will provision an isolated lab. On this validation host
    the default session is `running: false`.
  - The repository live-validation runbook explicitly forbids touching the live
    default Herdr session or fleet panes, which is the only way to bring the
    tripwire green.
  - The pinned v3.1.0 treehouse (the artifact this branch actually bumps) is
    proven live in treehouse-install-v3.1.0.txt: the SHA verifies, the archive
    installs, and the `--root` flag exists in --help output. That is the
    behavior the two Herdr E2E tests would exercise once past the tripwire.

To re-drive these two tests live, the operator must run them on a host with a
live default Herdr session (i.e., the standard Firstmate fleet already running)
so bin/fm-herdr-lab.sh's fleet-state tripwire passes; CI's Herdr lane satisfies
this by design.
